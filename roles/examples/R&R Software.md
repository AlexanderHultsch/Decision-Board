# Project Manager Software
level: 2
icon: code
perspective: Software scope, integration and test effort, ASPICE evidence and release timing

## Official description

*Taken from the internal role description. Kept word for word; edit only when the official document changes.*

Develop and maintain control over all the Program Management elements of the Software Swim Lane, such as:
- Project planning and strategy to meet company and Customer-defined milestones
- Process compliance (e.g., ASPICE, gate deliverables)
- Risk, defect and quality indicator tracking, including escalation handling
- Software-related budget and staffing forecasts
- Software project tracking tools and reporting structure

## Responsibilities

Manages one or more software projects from a governance perspective, coordinating with Software Swim Lane Leaders, including Functional Safety and Cybersecurity and other Project Managers. Responsible for project-wide alignment of milestones, budget tracking, and change control. Does not engage in low-level technical implementation or requirement definition but ensures that the delivery is aligned with the program-level plans.
Owns the consolidated view of Software Swim Lane planning and supports accurate impact assessment and forecasting of changes and gate approvals. Coordinates shared program dependencies (e.g., test software for manufacturing, BOM impacts, delivery tracking) and acts as a liaison for reporting and status updates to program leadership.
Collaborates with Program Buyers to estimate and manage external service activities related to software. Supports acquisition of required licenses and tools to enable software execution as per program needs. Focuses on removing roadblocks, escalating risk, and keeping alignment with broader project goals.
Follow Project Management Process and Tools. 
Drive work item status update in the central planning database.
Responsible to execute the CPM Epics is JIRA defined by Program Lead and drill down the activities. 
Create CPM Stories and Actions as necessary to achieve the CPM Epic objectives and deadline. 
Work with the Software, Functional Safety and Cybersecurity Swim Lane Leader on an accurate estimation of changes impact on the skill areas.

Software Project Manager Execution and Monitoring:
Leads and monitors the execution of software project activities, tracking internal and external milestones. Ensures delivery timelines, process compliance, cost control, and reporting discipline. Works closely with Software Swim Lane Leaders, Functional Safety and Cybersecurity and program teams to align decisions, resolve escalations, and plan effectively, promoting effective decision-making, leading with a structured approach to problem solving and triggering preventive actions at project level. Owns the software portion of the project budget and supports staff planning. Coordinates with other Project Managers to maintain cross-functional alignment on program-level targets.

Customer Focus:
Acts as the main point of contact for internal and external stakeholders regarding software delivery timelines and status. Ensures structured and clear communication across cross-functional teams. Supports external communications and escalations related to program milestones but does not lead requirement clarification or Customer negotiations.

Change Management:
Evaluates change requests for their impact on planning, resources, and costs. Supports the Change Manager and Program Manager in executing changes and keeping the plans updated accordingly.

Risk Management:
Tracks and mitigates software-related risks. Manages internal and external escalations, maintaining a proactive approach to avoid delivery disruptions.

Innovation and Technology Adoption:
Identifies opportunities to improve project execution using modern tools, methods, and best practices in project governance. Encourages continuous improvement in planning, monitoring, and reporting processes.

## Targets I am judged on

- Software gate deliverables and ASPICE evidence complete at each gate.
- Requirements implemented and verified against the release plan; defects closed by severity within the agreed time.
- Integration and test milestones met, including the software the manufacturing line depends on.
- Software effort and external service spend against forecast in the central plan.

## What I protect when I cannot have everything

Integration and test time. When a date is under pressure, I protect the
time between the last change and the release, and I give up scope - a
release that shipped untested costs more later than the feature was worth.

## How this lane usually fails

- Scope is added without effort being added. Early sign: a change accepted with "we can absorb that".
- A hardware or mechanical change is treated as software-free. Early sign: a change notice that lists no software impact at all.
- Test time is squeezed to hold a date, and regression is what goes first. Early sign: the test window shrinking while the content stays.
- ASPICE evidence is produced after the fact rather than as the work is done. Early sign: traceability updated in a burst before an assessment.

## What I decide alone, and what I escalate

- I decide: the internal release plan, how software work is broken down and sequenced, how effort is allocated inside the approved budget.
- I escalate to the Programme Lead: effort beyond forecast, a date that cannot be met without dropping content, anything touching functional safety or cybersecurity obligations.
- The Swim Lane Leaders decide: technical implementation and requirement detail - I do not.
