# Handover, 10 September 2026

For a fresh Claude Code session on `AlexanderHultsch/program-mind`. Read
this file first, then `docs/spec.md` section 11 (the work ahead) and the
vault guide `_How this vault works.md` (the vault's own specification,

## Who and what

Alex (Program Lead, Visteon, project MB32829 Dual DCDC) builds Program
Mind: a local site hosting AI agents on his Obsidian vault. The company
gateway model is `azure/Opencode-Kimi-K2.7` through OpenCode; the
gateway config `opencode.json` with the key lives outside the repository.

Two agents exist: the **Board** (a decision, every swim lane answering in
isolation, one consolidation) and **Ask the vault** (one agent, any
question, answers with sources and gaps, threads that stay open until
closed). Spec sections 3 to 10 are built; section 11 (the redesign) is
decided and step 1 of 5 is built.

## Rules that never change

- The vault is company confidential. Its content never enters the
  repository, a commit, a test fixture or a screenshot. Alex shares it as a
  zip in the chat when needed and gets a zip back.
- `config/config.local.json`, `config/threads/`, `audit/` and the vault are
  git-ignored and stay so. The company `opencode.json` stays outside the
  repository. The internal model is used for data security.
- Stdlib only, Python 3.11, no build step for the page, no dependencies.
- Every write into the vault is confirmed by Alex first. Threads and
  topics are stored next to the config, never in the vault.
- English throughout, plain, short sentences (spec section 7).

## Repository and workflow

- Repository renamed on GitHub to `program-mind` on 10 September 2026. Use
  the new URL: `git remote set-url origin https://github.com/AlexanderHultsch/program-mind.git`.
  The last session could push only through the old URL (its access was
  scoped to the old name); a new session started on the renamed repository
  should not have that problem.
- Branches: work on `claude-steps`, push it, then fast-forward `main`
  (`git checkout main && git merge --ff-only claude-steps && git push origin main`).
  Every commit ends with the two trailers the harness gives you
  (`Co-Authored-By`, `Claude-Session`).
- The gate before every commit: `sh tools/precommit.sh` (example config
  parses, the whole suite green: 268 tests at commit `cdd2be3`).
- The browser walk (Playwright, Chromium preinstalled in the cloud
  environment at `/opt/pw-browsers`): start
  `python3 tools/browser_walk/demo_server.py` and run
  `NODE_PATH=/opt/node22/lib/node_modules node tools/browser_walk/walk.js`
  from a folder where `shots/` may be written. It walks every screen of
  both agents against a fake model and prints `errors: []` when clean.
  Stop the demo server with `pkill -f demo_server.py`.
- Commit messages, PR bodies, code and comments carry no model name.

The page: `shell.js` defines `window.PM` (helpers, config, project picker,
options and statistics dialogs, the proposal screen, routes, the start
page) and boots on `DOMContentLoaded`. Each agent script calls
`PM.register({ id, match(pathname), render(route), onEnter, onLeave,
onPopState, boot, stats, statsExtra })` and owns its screens. Agent
scripts are served from `/static/agents/<agent>/<file>`.

Known wart: `knowledge/knowledge.py` imports `resolve_folder` from
`agents/board/roles.py` (to skip the roles folder when reading the vault).
A shared module depending on an agent; move `resolve_folder` into
`knowledge/` when convenient.
